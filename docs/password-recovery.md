# Восстановление пароля

На странице входа доступна ссылка «Забыли пароль?». Пользователь указывает email
и видит одинаковое подтверждение для зарегистрированного, неизвестного,
приостановленного или отключённого аккаунта. Письмо отправляется только
активному пользователю с установленным паролем, если лимит писем не исчерпан.

## Защита от частых запросов

- Одно подключение может отправить 5 запросов за 15 минут. Учитываются также
  формы с некорректным email. Следующий запрос получает страницу ожидания
  со статусом `429` и числом секунд в `Retry-After`.
- Для одного email суммарно допускаются 3 попытки отправки письма за 15 минут,
  независимо от количества подключений. Следующие запросы показывают то же
  подтверждение, но письмо не отправляют. Пауза не раскрывает, зарегистрирован
  ли адрес; счётчик ведётся и для неизвестных или неактивных аккаунтов.
- Разный регистр email, эквивалентные Unicode-символы и пробелы по краям
  не создают отдельный лимит. При этом сама форма по-прежнему проверяет
  допустимость email.
- Просмотр страницы и отклонённые CSRF-защитой запросы не расходуют лимит.
  Отказы не продлевают 15-минутное окно. Ошибки доставки расходуют попытку:
  автоматической повторной отправки нет.
- Счётчики восстановления отделены от счётчиков обычного и административного
  входа. Ограничение писем не блокирует вход, не завершает сеансы, не меняет
  статус пользователя и не отзывает уже выданную действующую ссылку.

Счётчики общие для всех процессов сайта и хранятся в существующей служебной
таблице. HMAC-ключи не содержат открытых email или IP-адресов. Старые окна
удаляются ограниченными партиями по правилам из [защиты входа](login-protection.md).
Доверенным источником IP остаётся серверный `REMOTE_ADDR`; перед установкой
прокси необходимо настроить его корректную передачу.

При недоступности счётчиков письмо не отправляется; сайт возвращает общее
сообщение `503` и предлагает повторить через минуту. Ответы запросов и страницы
с токеном не кешируются. Для страниц подтверждения и ошибок восстановления
установлен `Referrer-Policy: no-referrer`.

## Одноразовая ссылка

Ссылка действует один час. После её открытия Django переносит токен в сеанс
браузера и перенаправляет на адрес без токена. При отправке нового пароля сайт
заново читает пользователя под блокировкой базы, проверяет текущий статус
и токен и сохраняет пароль в той же транзакции. Два браузера, одновременно
отправляющие одну ссылку, не могут по очереди перезаписать пароль: сработает
только первая успешная отправка.

Приостановленный, отключённый, приглашённый, неактивный пользователь или аккаунт
без установленного пароля не может воспользоваться ранее выданной ссылкой.
Повторное открытие уже заполненной формы также проверяет текущий статус.
Смена пароля, email, последний вход и истечение срока проверяются стандартным
токеном Django. Новый пароль проходит действующие валидаторы; ошибка заполнения
сама по себе не расходует ссылку.

После успешного восстановления предыдущие сеансы теряют авторизацию при
следующем обращении. Автоматический вход не выполняется: пользователь входит
с новым паролем через обычную форму.

Ожидание каждой блокировки базы при сохранении ограничено двумя секундами.
При ошибке базы транзакция смены пароля откатывается, а пользователь получает
общее сообщение без внутренних подробностей.

## Текущие ограничения

В локальном режиме письма выводятся в журнал контейнера. Настоящая SMTP-доставка
и HTTPS пока не развёрнуты. Реальные письма в проверках не отправляются.
Для публичного запуска потребуется подключить почтовый сервис и проверить
защищённые ссылки с корректным доменом.

Отправка письма пока синхронная: одинаковый текст ответа не гарантирует одинаковое
время ответа для существующего и неизвестного email. Отдельной очереди доставки
и автоматического уведомления о смене пароля пока нет.

Лимит на email временно может задержать новое письмо после чужих запросов;
используйте уже полученную действующую ссылку или подождите окончания окна.
При возврате аккаунта из приостановленного в активное состояние старая ссылка
может снова работать в пределах своего часа, если пароль, email и последний
вход не изменились. Текущая проверка статуса не является постоянным отзывом
всех ранее выданных ссылок.

## Проверка

```sh
docker compose exec -T web python manage.py test accounts.test_password_reset accounts.test_password_reset_limits accounts.test_password_reset_security --keepdb
```

Не запускайте два набора тестов одновременно с одной тестовой базой.
Проверки покрывают лимиты, ошибки, CSRF, истечение ссылки, смену статуса/email,
инвалидацию сеансов и конкурентное применение ссылки на PostgreSQL.
Все 25 проверок восстановления входят в успешно пройденный полный набор
из 191 теста проекта.

Решение опирается на [стандартное восстановление пароля Django](https://docs.djangoproject.com/en/6.1/topics/auth/default/#django.contrib.auth.views.PasswordResetConfirmView)
и меры против массовых запросов из [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
Пороги 5 и 3 за 15 минут — правила этого проекта.
